# Preserving handoff

Project-authored workflow. Read root/app AGENTS, `docs/handoff.md` and the relevant task rows. On resume, inspect actual Git and tool state before trusting recorded process IDs, branch tips or test counts. Follow `docs/astra/branch-transition.md` when adopting the guidance branch; the prior Windows main checkout contains unpublished work.

Identify committed, staged, unstaged and untracked changes and their ownership. Keep the current implementation, original archive, historical evidence and other worktrees intact. Missing local access does not make the committed GitHub baseline equivalent to the latest dirty implementation.

For an implementation assignment, continue with a concrete code correction and verification; do not turn this workflow into a documentation-only substitute. Before a checkpoint review explicit diffs, test the coherent source and stage only intended files. Do not reset, clean, indiscriminately stage, force-push or manufacture evidence to obtain a clean-looking tree.

Update the handoff with actual commit/push state, tested candidate identity, observed server/build ownership, behavior changed, exact executed checks, evidence paths, failures, residuals and the next concrete defect. Label historical observations and unverified pending work. A skipped or queued check is not passed; a self-review is not independent review or owner approval.

Keep acceptance only in `docs/tasks.md`, findings in the audit and decisions in the decision register. Preserve failed attempts and junction-backed storage. Never promise unconfigured background work or claim a tool/browser/model configuration was installed without checking it.

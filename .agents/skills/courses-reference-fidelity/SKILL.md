# Reference fidelity

Project-authored workflow. Follow root/app AGENTS and preserve the current branch/worktree boundaries. Read the owning task rows, current audit and only the needed runbook sections.

Open the exact immutable original and confirm source identity, viewport, state, scroll and variant. Inspect the active component/imports and actual browser before editing. Establish a stable baseline with source/QA/browser identity; do not assume a fixture or dev server matches the latest code.

Correct wrong content and scenario state before geometry, typography, crop and material. Prefer one bounded owner correction over per-screen forks or generic theme replacement. Preserve legitimate live controls and shared state when fixture hints clear.

Capture the same candidate state at the exact source viewport, inspect the complete source/render/diff at readable size, and exercise affected real controls. Compare live endpoints with direct fixtures when relevant. Run focused regressions for local edits and the full corpus for shared shell/state/style changes; check optimized output for runtime-sensitive behavior.

Record task IDs, hashes, viewport/crop, environment, reviewer, evidence path, residuals and regressions. Keep failed attempts and unresolved discrepancies. Do not mask product pixels, resize originals, substitute screenshot UI, relax thresholds, distribute fonts or check MATCH solely from metrics. No course adaptation or owner acceptance follows from this workflow.

Detailed commands: `docs/development.md`. Evidence criteria: `docs/quality-and-operations.md`. Visual contracts: `docs/design-system.md`.

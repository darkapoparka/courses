# Task prompts for Astra

Use a clear outcome, the actual constraints and observed completion evidence. The root contract owns durable rules; do not paste every document into every task. These are project templates, not hidden reasoning requests or promises of autonomous background work.

## Resume implementation

```text
Resume the existing Apple Music clone, not documentation-only work.
Read AGENTS.md, docs/handoff.md and the relevant docs/tasks.md entries.
Work in J:\courses; main is the integrated baseline. Inspect the actual
branch, status and docs/astra/branch-transition.md before choosing a bounded
feature branch or using an assigned worktree. Preserve unfinished work from
other sessions and original preview evidence. Do not repeat completed
transfers or assume GitHub includes local edits.

Choose the highest-impact currently evidenced discrepancy in the active
implementation. Open the exact originals, establish a stable baseline,
implement a bounded correction, compare the live and fixture states, and
exercise the recorded controls. Use focused checks for local work and the
full corpus after shared shell/state/style changes. Verify optimized
production behavior for runtime-sensitive changes. Continue with concrete
implementation while authorized scope and available tools allow.

Do not add courses, scaffold web/, change the framework, fabricate state
transitions or mark acceptance from route counts. Checkpoint coherent
verified changes only on the authorized branch. Report the actual source,
changes, tests, residuals, commit/push state and next defect. Report genuine
access blockers without pretending that tests or work happened.
```

## Bounded visual correction


## Recorded journey

```text

through every recorded step using real controls. Capture intermediate,
scroll, menu/form and return states with ordered non-overwriting evidence.
Compare live states to originals and direct fixtures. Investigate differing

Keep route coverage, behavioral tests and complete FLOW acceptance separate.
```

## Review

```text
Review this exact candidate and its owning task evidence for correctness,
visual/state regressions, missing controls and unsupported acceptance claims.
Prioritize findings that would change a user's experience. Cite affected
files/state IDs and observed evidence; do not invent an independent test or
reviewer. Where tools permit a separate reviewer, give that reviewer a
bounded read-only scope and identify their actual result. Otherwise label
this as self-review. Do not rewrite the whole app during a review task.
```

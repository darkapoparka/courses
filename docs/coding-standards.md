# Coding standards — exact behavior before fashionable rewrites

## Current clone

Trace the active component and imported style before editing. Preserve fixture identities, local-preview boundaries and meaningful live navigation. Do not replace the existing scene system as an incidental cleanup task. Change the smallest owner that fixes the actual defect, then check all dependent states.

Use strict TypeScript and explicit state transitions. Validate external inputs with bounded types; do not spread `any`, unsafe casts or disabled checks through the project. Prefer concrete small functions over generic controllers, repositories, factories or provider wrappers with no current consumer.

Keep local interaction state distinct from persistent application/scenario state. Initial fixture values must yield to real controls without resetting unrelated account, catalog, queue, selection or library data. Derived values should have one owner; avoid effects that continually mirror or overwrite another state source.

Use semantic controls, accessible names, meaningful links, keyboard operation, focus containment/return and real disabled/pending/error states. Do not use screenshot overlays, hotspots, invisible duplicate controls, forced-click-only hit targets or buttons that merely pretend an action succeeded. Local preview behavior must be explicit and must not send real credentials or payments.

## Visual implementation

Match the selected original's dimensions, content, typography, crop, scroll and state. Reuse accurate components; avoid arbitrary theme defaults, replacement icon families or speculative gradients. Inspect computed browser output as well as CSS source, especially after optimized builds. Preserve standard/prefixed backdrop declaration behavior and live material transitions.

Use explicit UTF-8. Keep scripts reproducible outside one machine's scratch directory. Do not modify frozen originals, generated acquisition reports or baselines to make a test pass. Proprietary fonts and source artwork are not new assets to distribute.

## Verification and changes

A source edit needs appropriate type/build and behavioral evidence; a shared UI/state/style edit needs the complete corpus and regression review. Documentation-only edits need document checks. Never claim an unavailable script ran. Register browser suites before counting them, preserve failed runs and record the exact tested candidate.

Keep changes cohesive. Do not mix an unrelated dependency upgrade, formatting sweep or architecture migration into fidelity work. Stage explicit files, review the staged diff and preserve another session's pending work. The handoff names exact checks, residuals and actual commit/push state.

## Requirements for later integrated course code

After the phase gate, keep server-only secrets, signing, data queries and authorization out of client bundles. Server actions and HTTP handlers must validate identity, resource relationships, payload limits and authorization at the operation itself; a parent layout or hidden UI is not an access boundary. Return minimal safe view models, not private rows that the browser hides.

Use request-scoped identity contexts and least-privilege database access. Separate public metadata from protected lesson material. Test grants/policies and direct requests with actual anonymous, learner and cross-workspace identities, not only privileged credentials. A sequence of independent writes is not a transaction; money, grants and publication invariants need a checked atomic path.

Prefer restricted Markdown/plain text without executable MDX, raw creator HTML or arbitrary scripts. Preserve user input on validation/conflict errors. Use version checks for authoring, notes and progress; stale updates must not overwrite newer state or undo completion.

Measure actual performance before adding caches or state frameworks. Bound queries, pagination and media sizes; do not optimize by bypassing authorization. New dependencies need a current use, version/lockfile review and relevant tests. No invented social proof, earnings, qualifications or production-integration success.
